# 🧪 Автоматизация UI & API тестирования веб-приложения Stellar Burgers

Проект демонстрирует навыки построения продвинутого автотестового фреймворка, объединяющего сквозное UI-тестирование (Page Object Model) и работу с API-слоем для подготовки тестовых данных и конфигурации окружения.

---

### 🛠 Стек и инструменты: Java 11, JUnit 4, Selenium WebDriver, WebDriverManager, REST Assured, Lombok, Java Faker, Gson, Allure Report

---

### 📝 Описание проекта
**Stellar Burgers** — сервис заказа космических бургеров. В рамках этого проекта автоматизированы пользовательские сценарии (регистрация, многоканальный вход, навигация в конструкторе) с параллельной поддержкой бэкенд-конфигурации (создание и удаление сущностей через API).

**Цель работы:** Реализация архитектурно правильного фреймворка для кроссбраузерного UI-тестирования с оптимизацией скорости выполнения тестов за счет API-методов.

---

### 🚀 Выполненные задачи и результаты

#### 🔹 Часть 1: Архитектура фреймворка и управление драйверами
* **Паттерн Factory Method (`FactoryDriver`):** Реализовала класс-фабрику, унаследованный от `ExternalResource` (JUnit 4 Rule). Он инкапсулирует логику инициализации, настройки и автоматического закрытия сессий браузеров.
* **Паттерн Page Object Model (POM):** Вынесла интерфейс страниц (`BasePage`, `MainPage`, `LoginPage` и др.) в изолированный слой `pages`, полностью разделив локаторы, бизнес-логику страниц и сами тесты.
* **Централизованная конфигурация:** Разделила константы проекта на два конфигурационных класса:
  * `AppConfig` — базовые URL-адреса и пути фронтенд-страниц.
  * `ApiConfig` — ручки (endpoints) API для бэкенд-взаимодействия.

#### 🔹 Часть 2: Интеграция с API и оптимизация тестов
* **API-Предусловия (REST Assured):** Интегрировала REST Assured непосредственно в UI-проект. Это позволило автоматизировать рутину (например, создание уникального пользователя через `UserSteps` перед UI-тестом авторизации и его гарантированное удаление после теста через `@After`).
* **Оптимизация и дата-генерация:** Использовала **Lombok** для чистоты POJO-моделей данных (`UserModel`, `LoginModel`) и **Java Faker** для динамической генерации параметров.

#### 🔹 Часть 3: Кроссбраузерные UI-сценарии
* **Кроссбраузерность:** Обеспечила стабильный запуск и прохождение всех тестов как в **Google Chrome**, так и в **Яндекс Браузере**.
* **Покрытие сценариев:** Автоматизировала валидацию длины паролей при регистрации, проверку **4 независимых точек входа** в систему и корректность навигационных табов «Конструктора» («Булки», «Соусы», «Начинки»).

### 📂 Архитектура проекта
```text
src/main/java/
├── config/         # Конфигурация URL приложения и эндпоинтов API (ApiConfig, AppConfig)
├── data/           # Генерация динамических тестовых данных (UserData)
├── model/          # POJO-модели данных с использованием Lombok (UserModel, LoginModel)
├── pages/          # Паттерн Page Object — описание страниц UI (BasePage, MainPage и др.)
└── steps/          # API-клиенты для выполнения фоновых запросов (UserSteps)
src/test/java/
├── base/           # Инициализация и управление жизненным циклом драйвера (FactoryDriver)
└── tests/          # Тестовые сценарии (ConstructorTest, LoginTest, RegisterTest)
```

### 🏃 Инструкция по локальному запуску

**Как запустить тесты и открыть Allure:**
1. Клонируйте репозиторий и перейдите в папку проекта:
   ```bash
   git clone https://github.com
   cd Diplom_3
   ```
2. Запустите автоматический прогон кроссбраузерных тестов:
   ```bash
   mvn clean test
   ```
3. Сгенерируйте интерактивный Allure-отчет для детального анализа шагов:
   ```bash
   mvn allure:serve
   ```
